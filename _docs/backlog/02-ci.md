title: CI: run unit and integration tests on every pull request and push
labels: groomed,ci
---
## Goal

Every pull request and every push to `main` runs all test suites on GitHub Actions, so a broken change is visible before merge.

## Acceptance criteria

- [ ] `.github/workflows/ci.yml` triggers on `pull_request` and on `push` to `main`
- [ ] Backend unit tests (`uv run pytest`) and frontend tests (`npm ci && npm test && npx tsc -b`) run as two parallel jobs
- [ ] An `integration` job starts Postgres 17, Redis 8 and Redpanda as service containers and runs `uv run pytest tests_integration` with `TEST_DATABASE_URL`, `TEST_REDIS_URL` and `TEST_KAFKA_BOOTSTRAP` set; all integration tests pass and none are skipped
- [ ] The `integration` job runs only after both unit jobs pass
- [ ] A `build` job runs `docker compose build` after the integration job
- [ ] `ruff check` runs in the backend job and fails the job on errors
- [ ] A pull request with a deliberately failing test shows a red check; reverting it shows green
- [ ] README shows the CI status badge

## Out of scope

- Pushing images and deploying (#CD issue)
- End-to-end browser tests (#E2E issue)

## Constraints

- Python is set up with `astral-sh/setup-uv` (uv 0.13, Python 3.14); Node 22
- Cache uv and npm downloads
- No secrets are needed for this workflow
