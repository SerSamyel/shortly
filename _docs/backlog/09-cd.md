title: CD: build once, deploy to dev on main, manual promotion to prod, rollback
labels: groomed,ci,deploy

## Goal

Every merge to `main` reaches dev automatically, prod gets exactly the image tested in dev only after a manual approval, and a bad release can be rolled back in one action.

## Acceptance criteria

- [ ] On push to `main`, after CI passes, the image is built once and pushed to GHCR with tag `YYYYMMDD-HHMMSS-<shortsha>`
- [ ] The same workflow runs `helm upgrade --install` in the `dev` namespace with that tag and checks `/health` returns 200 with the new version
- [ ] Workflow `promote-to-prod` (manual `workflow_dispatch`) reads the tag currently deployed in dev and deploys it to `prod`; it uses the GitHub environment `prod`, which requires approval
- [ ] Workflow `rollback-prod` (manual) deploys a tag given as input, or the previous Helm revision when the input is empty
- [ ] Cluster credentials are stored as GitHub environment secrets (`dev`, `prod`), scoped to their namespace
- [ ] README documents how to promote and how to roll back

## Out of scope

- Blue-green or canary releases

## Constraints

- Never rebuild an image during promotion
- The deploy job fails if the health check does not report the expected version within 2 minutes
