## Goal

One Playwright test proves the key user journey works across the real stack: frontend, API, Redis, Redpanda, consumer and Postgres.

## Acceptance criteria

- [ ] `e2e/` contains a Playwright (TypeScript) project with its own `package.json`
- [ ] The test signs up a fresh user, creates a link with a random alias, opens the short URL in a second browser context and checks it lands on the target URL
- [ ] Back in the first context, the link page shows `1` total click within 30 seconds (polling the page, not sleeping a fixed time)
- [ ] `make e2e` and `scripts\check.cmd e2e` run the test against `docker compose up` on http://localhost:8000
- [ ] The test target URL is a page served by the stack itself or `https://example.com`; no other external sites
- [ ] The CI workflow runs the E2E test after the build job and uploads the Playwright report on failure

## Out of scope

- Visual regression testing
- Testing every page; one journey is enough

## Constraints

- Do not change application code to make the test pass; if a selector is missing, add an accessible label instead of a test id
- Follow `_docs/testing-guidelines.md`
